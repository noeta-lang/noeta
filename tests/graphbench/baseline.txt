# Baseline for `cargo run -p noeta-graphbench` — one row per (arm, category).
#
# `f1` is the floor and `tokens` is the ceiling. A default run compares against them and
# exits non-zero when an F1 falls below its floor or a row's tokens-per-question rises
# above its ceiling.
#
# TOLERANCE. F1 may fall by 0.0005, which is half of the last printed digit and therefore
# rounding; tokens may not rise at all. The bands are that tight because nothing in this
# measurement varies: the retrieval layer has no model in it, no sampling, no clock in any
# answer, and no dependency on machine speed, so two runs of one tree produce byte-equal
# numbers. That is the difference from the instructions-retired perf ratchet, whose bands
# exist because a hardware counter has spread. Here a row that moved, moved because the
# code moved.
#
# Wall time is recorded in `--json` and gated nowhere: this box carries several concurrent
# agent builds, so a millisecond column measures the afternoon.
#
# An arm that reports SKIP has no row. A SKIP is never a pass, and a baseline that recorded
# one as a zero would turn "the tool does not exist yet" into a measurement.
#
# Re-record with:  cargo run -p noeta-graphbench -- --record
# Read the diff's sign: F1 up is an improvement worth pinning, F1 down needs a reason, and
# tokens up needs the sentence saying what the extra context bought.
