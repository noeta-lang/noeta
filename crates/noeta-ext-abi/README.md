# noeta-ext-abi

The native-extension ABI (P-NATIVE): the contract a crate implements to register native modules and first-class types into the language, plus the dep-free primitives both backends and the front end share.

- **Takes in:** nothing beyond `serde`/`compact_str`/`equivalent`/`hashbrown` — deliberately dependency-lean.
- **Emits:** the `Extension` trait and the registration vocabulary (`ExtModule`/`ExtType`/`ExtClass`/`ExtEnum`/`ExtStruct`/`ExtTrait`/`ExtFn`, `NativeValue`/`NativeOut` marshalling), the `Host` capability supertrait (`Clock`/`Console`/`Entropy`/`Env`/`FileSystem`/`Ids`/`Network`/`Os`/`P2p`/`Rng`), `NativeCtx`/`CtxDispatch` for host re-entry, and the `registry` module that is the single source of truth for what's registered.

It also carries `render_hint`, the shape of "how do I write this out?" for the one case where a value cannot answer for itself. A fixed-width integer is erased to its 64-bit word, so an unsigned value past bit 63 is a negative word and would be written — and ordered — as its signed reinterpretation; the signedness lives only in the static type. A `RenderHint` names the *positions* under which the checker found one — the value itself, a list's elements, a map's keys and values, a tuple's or object's slots, an enum's per-variant payload — and both backends walk their own value model against that one description. It lives here, not in the AST, because everything the walks touch is here: the one `json_text` encoder every unhinted subtree delegates to, the `MapKey` a rendered map's keys go through, and the `NativeValue` tree both backends deep-marshal into. A native type may declare that a method *keeps* one of its arguments for a later serialization (`ExtType::push_hint_args`), and the dispatch reads that argument's hint as `NativeCtx::push_hint` — which is what a value pushed on a flush tick, long after its call site is gone, needs to be written correctly. One position under a hint is not a property of the site at all: inside a generic body the door's static type names a *type parameter*, whose width the instantiation decides, so the hint carries a `RenderHint::Param` and the program's `TypeArgHints` table says what each instantiation makes of it. `resolve_hint` splices the two, against whichever channel the enclosing body has — a generic `fn`'s hidden type-argument slot, or a generic type's receiver tag, since a method's name-keyed entry points bind positionally and can take no hidden slot. A parameter neither channel can name resolves to nothing, which is the same untouched path a `dyn` takes. An instantiation a generic body *builds* out of its own parameters — `wrap([v])` inside `fn built<T>(v: T)`, at `List<T>` — sits on neither channel whole, since no signature names it and no caller could have interned it; a `HintComposition` is the arithmetic that answers it from the slot carrying its leaf, precomputed per combination of leaf values and applied by `compose_type_arg`. A kept hint is spliced at the call that binds the value, because the tick that serializes has no frame to splice against.

The registry **validates the assembled unit set before it starts** (`Registry::new`/`try_new`), and refuses rather than shadowing or dropping: duplicate identities, a namespace outside the unit's own root, a directive illegal for the kind that carries it, a required parameter after an optional one — and every **stringly-typed cross-reference**, meaning any field whose value names something declared elsewhere. A `traits` entry naming a built-in or native trait, a `SigType::BoundedVar` bound, a `SigType::Assoc` projection, a `docs` key, a tier's `config` attribute and expression `handler`, a tier runner's tier, a derive method's handler, a backed enum's variant constants. Those share one failure mode and it is why they are checked here: an unresolved name is **silently absent**. Every consumer is a lookup that yields nothing and moves on, so the trait is simply not held, the doc simply not shown, the runner simply not found — `traits: &["Comparbale"]` compiles, registers nothing, and leaves the type unordered with nothing to notice. Assembly is the one point every path passes (CLI, composed shim, embed session, lazy default), so it is where the name has to resolve.

Split out of `noeta-stdlib` so the contract does not drag core's batteries (crypto/UUID/JSON): a third-party extension — and internal mid-end crates like `noeta-ir` — depend on this lean crate, while `noeta-stdlib` re-exports it (`pub use noeta_ext_abi::*`) and adds the concrete `std` modules on top, mirroring Rust's `core`/`std` relationship. It also carries the `ABI_VERSION` constant (bumped on any change to the registration/dispatch contract), the command surface (`ExtCommand`, for extension-provided CLI verbs), and the `net`/`stream`/`os`/`p2p`/`telemetry` capability vocabularies. The `stream` module additionally carries real *behavior* rather than only vocabulary — the incremental `FrameDecoder` behind `std.http.client.stream`, which is dependency-free precisely so the deterministic sandbox and the real reqwest-backed host cut bytes into frames with one parser and cannot disagree. See `plans/native-abi/README.md`.

Part of the `noeta` compilation pipeline (see the repository `ARCHITECTURE.md` and `AGENTS.md`).
