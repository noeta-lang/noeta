# noeta-check

The type checker: the inferred-static front-end between parsing and compilation.

- **Takes in:** `Program` (from `noeta-ast`), reasoning in `Type` (from `noeta-types`).
- **Emits:** `check(&Program) -> Vec<Diagnostic>` — the type errors found (empty ⇒ well-typed). This is the body of the `checked` salsa query in `noeta-db`, slotted between `ast` and `bytecode`.

## A shared front-end

The checker runs upstream of *both* backends (in the conformance harness, the differential, and `noeta run`). A program it rejects never reaches the reference backend (`noeta-eval`) or the VM, and its diagnostics are the program's whole observable result — identical regardless of which backend would have run. That is what lets the checker promote runtime errors to compile-time ones while keeping the differential oracle green by construction, and lets a negative type-error case assert via the ordinary `// expect: error EXXXX` header.

## Inferred-static, with an interior inference hole

Every expression gets an inferred `Type`. Signatures are **required at named boundaries** (a missing parameter or return type is `E0022`) and inference runs locally in bodies, with `Type::Unknown` as the fallback wherever a type is genuinely not yet known (e.g. an erased generic parameter). A check suppresses itself on an `Unknown` operand, so the *interior* tolerates an inference hole by design — but holes are eliminated at typed boundaries, so a program with an un-inferable binding (`E0023`) or a missing signature (`E0022`) is rejected, and `dyn` is the one explicit dynamic escape.

## What it checks: control flow and arithmetic

- **Exhaustive `match`** (`E0011`) — a concretely-typed enum / `Result` / `Option` scrutinee missing a variant with no catch-all. A **guarded** arm (`pattern if cond`) contributes nothing to coverage — the checker cannot prove a guard ever true — and the guard itself is checked as a `bool` position with the arm's pattern bindings in scope.
- **Unreachable `match` arm** (`E0066`) — an arm after an unguarded *irrefutable* one (a `_` wildcard, or a bare identifier that is genuinely a binding, both of which compile to no test at all). Decidable from the arm list alone, and an error rather than advice: the arm is dead code the author did not intend, and unlike an always-false type test nothing in the source reveals it.
- **Bare payload-free variant patterns** — a bare-identifier pattern whose name is a **payload-free variant of the scrutinee's own enum** (`String => …` on a `Type` that declares `String;`) resolves to that variant: it binds nothing, it is refutable, and it counts toward `E0011` coverage. Everything else stays a binding — resolution is scrutinee-directed, so another enum's variant name, or any name against a gradual/`dyn` scrutinee, binds as before; nested patterns resolve against the *field's* type. `Checker::payload_free_variant` is the single judgement, consumed by all three (`check_arm_reachability`, `match_coverage`, `bind_pattern`), and `bind_pattern` records the span in `Sites::variant_pattern_sites` so the IR lowering rewrites it into an ordinary `Pattern::Variant` for both backends. (This retired `E0067`, which reported the old always-binds reading of the same spelling; the code number is never reused.)
- **`?` on a non-fallible value** (`E0012`) — `expr?` where `expr` is statically neither `Result` nor `Option`.
- **`?` where the early return has nowhere to go** (`E0012`, the same code — it is the same rule at the same span) — the **position rule**, one judgement over both halves: `?` on an `Option` early-returns `none`, so the declared return has to be a `?T` (`check_try_option`); `?` on a `Result` early-returns the `Err`, so it has to be a `Result<T, E>` (`check_try_error`). A declared return that *defers* — `dyn`, an inference hole, top-level code, an unannotated closure — still defers, and an `Err` that reaches the top aborts at runtime with `E0069` rather than being discarded. Missing the `Result` half was the language's quietest hole: `fn work(): void { client.get(url)? }` checked clean, dropped the transport failure, and exited 0.
- **Arithmetic type mismatch** (`E0007`) — `+ - * / %` on a concretely non-numeric operand, reusing the runtime `TypeMismatch` code at the same span.

## What it checks: traits, impls and attributes

- **Unknown trait** (`E0014`) — an `impl Trait { ... }` block names a trait that is not a built-in, or a `@derive(Trait)` directive names nothing any derive route registers, or names a built-in the compiler carries no recipe for. Validated against the `BuiltinTrait` registry in `noeta-types`; the refusal names the routes still open to the trait in hand (`via:` delegation, an explicit `impl`), since a built-in without a recipe is not thereby underivable.
- **Invalid impl** (`E0015`) — an `impl` block does not satisfy the trait it names: the trait's required method is missing or has the wrong arity (e.g. `impl Add` without an `add(other)` method).
- **Coherence — uniqueness** (`E0027`) — a second implementation of a trait a type already has, counting `@derive(T)`, an in-body `impl T { }`, and a standalone `impl T for Type { }` alike. The diagnostic labels **both** sites (the offending one and the one it collides with), because the two are routinely in different modules and a single-site report cannot be acted on.
- **Coherence — the package orphan rule** (`E0070`) — a standalone `impl Trait for Type` in a package that declares neither the trait nor the type. Read off the loader's per-source `PackageMap` (`noeta_span`), never off a namespace prefix: a namespace is declared per file with no required relationship to the package that shipped it. Where provenance is unknown — a single-file check, a REPL fragment, generated code — the rule stands down rather than guessing. Built-in and native traits belong to no package and so cannot be the local end. Cross-*module* impls inside one package are unaffected; the boundary is the package.
- **Invalid attribute** (`E0017`) — a `#[...]` data attribute is malformed or misused — currently `#[derive(...)]` in data-attribute position. Code generation is the separate `@derive(...)` directive; `#[...]` is for data attributes only.

## One trait-membership question

"Does this type implement that trait" is asked in one place, `Checker::implements_trait`, for built-in, user-declared and native traits alike. It is the static counterpart of the reflection table (`noeta_ast::reflect::ReflectionInfo::type_implements`) that the runtime `x is dyn Trait` / `x.as<dyn Trait>()` test and the `traits_of(x)` query read, and both are fed by the same four declarations: an in-body `impl Trait { … }`, a standalone `impl Trait for T`, a `@derive(Trait)`, and a native type's ABI advertisement.

Routing the `dyn Trait` coercion through that one funnel is what makes three surfaces agree by construction rather than by coincidence — "widens into `dyn Trait`", "`x is dyn Trait`", and "a `Trait` method call on `x` resolves". Asking the question of one table per trait *kind* is how they came apart: with the coercion reading the user-trait table alone, every built-in trait answered `false` to it while the runtime test answered `true`, so a value could be tested against `dyn Error` and narrowed into the branch while no `dyn Error` could be formed anywhere.

Which built-in traits have a trait object at all is derived from the trait's own row (`BuiltinTrait::has_trait_object`), not from a list of names: the trait must impose a required method (a marker has nothing to dispatch), that method must be an instance method (a `static` one is called on the type, so there is no receiver to erase), and `dyn Name` must name the trait completely (the surface has no `dyn Name<…>`, so a parameterized trait has no full spelling). `dyn` on a trait that fails any of those is `E0014` at the annotation.

## What it checks: name and type resolution

- **Unknown type** (`E0013`) — a type annotation (parameter, return, field, enum backing, or generic argument) naming a type that resolves to nothing: not a built-in, not one of the bare prelude spellings (`list`/`map`/`set`/`Ordering`), not a declared struct/class/enum, not a name brought in by a `use`, and not a generic parameter in scope. It depends on module resolution: "undeclared" is only distinguishable from "valid but imported" once the loader has merged resolved imports into the program and left opaque-stub `use`s in place, which puts both referents in front of the collect pass — so an unresolvable name here is genuinely unknown.

These are declaration-level checks (they never touch expression typing), so a correct program emits nothing and the differential oracle is unaffected. Code generation (`@derive(...)`) and data attributes (`#[...]`) are two distinct decorators with two distinct sigils: `@derive` names a built-in recipe the compiler synthesizes, a user trait, a method bundle, or an extension-registered recipe; `#[...]` attaches a struct as metadata (collected into the queryable build manifest; a `#[Foo(...)]` use is gated on `Foo` being a struct marked `@attribute`, with its arguments checked as a construction of `Foo` — E0029/E0009/E0007/E0005). The *behavior* the traits drive is wired in both backends (`noeta-eval`, `noeta-vm`): every operator is trait-dispatched — `+ - * / ~` (`Add`/…), `==`/`!=` (`Equatable`), and `< <= > >=` (`Comparable`, via the built-in `Ordering` enum + `.compare()`). The protocols dispatch too: `a[i]` via `Index` (`get`, over lists/maps/strings with built-in fallback, `E0016`/`E0018`), `len(o)` via `Length`, `echo`/interpolation via `Display` (`to_string`), and `for x in o` via `Iterable` (`iter`). Two derives synthesize genuinely-new behavior — `@derive(Comparable)` (structural field-wise ordering) and `@derive(Serialize<Json>)` (structural JSON) — while `Equatable`/`Display` are the structural defaults every value already has, made *nameable*: the derive registers the trait's method (`noeta_ast::derive::DERIVED_BUILTIN_METHODS`) so `x.eq(y)`/`x.to_string()` type here and dispatch in both backends, keeping `x is dyn Display` and "calling a `Display` method on `x` works" from disagreeing. `Clone` registers membership alone — it imposes no method. `obj(args)` dispatches through `Callable` (`call`) and a named member read through `Members` (`get`), on the same registry. Generics are erased: `class Box<T>` parses, checks with the type parameter treated as `Unknown`, and runs with `T` erased at runtime.

Inference is **bidirectional checking with local inference**, deliberately *not* Hindley–Milner — subtyping (`dyn` widening, directional method resolution, struct width) is load-bearing and defeats HM's symmetric unification. What that buys: required signatures at named boundaries, checked arguments and returns, the `E0023` binding endpoint, bounded generics, trait coherence, `dyn` narrowing, and declared unions — with only an *interior* inference hole tolerated by design.
