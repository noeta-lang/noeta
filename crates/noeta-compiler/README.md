# noeta-compiler

The bytecode compiler: AST → `Module`.

- **Takes in:** an AST `Program` (from `noeta-ast`); `is_prelude_name` (from `noeta-builtins`). Internally it lowers to the **Core IR** (`noeta-ir`) and runs the precise-RC passes (`noeta-ir-passes`: liveness → drop insertion → reuse) before emitting bytecode, so the VM executes the *same* RC-annotated program the reference backend does.
- **Emits:** a `noeta-bytecode` `Module` (the prototype table), or `Unsupported` for any construct outside the VM's subset (essentially never for real programs — the VM covers the whole language).

It lowers essentially the whole language: literals and bindings, arithmetic/comparison/logic and `~` concatenation, functions and **closures** (arrow and block, the `|>` pipeline), collections and their builtins/methods, string interpolation, the **object model** (structs/classes/enums on shapes, all-fields/`..spread`/defaulted literals, member access, associated functions and instance methods), tuples, generics, trait/operator dispatch, `match`/`?`/`??`, unions and `is`/`.as<T>()` narrowing, generators and `async`/`await`, isolates and channels, and packed value types. Names resolve through a two-level model: frame-local registers for parameters/locals (a method's register 0 is the receiver, its field names resolving against it) and a by-name global table for function names, imports, and the top-level bindings something outside the top level can reach — a top-level binding nothing else can name lives in `main`'s registers instead (`TopLevelStorage`, decided per binding by `promotable_top_level` and verified after the entry chunk compiles), so the same loop costs the same at the top level as inside a `fn`; a nested closure captures its free variables as **upvalue cells** (`MakeClosure` with `CaptureFrom::Local`/`Upvalue`, closure conversion in `freevars.rs`). Register allocation is a reuse-aware graph-coloring post-pass (`regalloc.rs`), which also emits the **last-use release for a stale global read** — the retained copy a `LoadGlobal` leaves in a register when the same statement goes on to take that global out of its slot for an in-place self-update, so `m[k] = m.get_or(k, 0) + 1` at the top level reuses the map instead of copying it. A three-pass compile registers every top-level `struct`/`class`/`enum`/`use` first (so forward references and shapes exist), then compiles class methods, then the top-level program. The lowering mirrors the reference backend's evaluation order and exact diagnostic text/spans so the differential oracle sees identical `RunResult`s.

Part of the `noeta` compilation pipeline (see the repository `ARCHITECTURE.md` and `AGENTS.md`).
